# محمد — دفتر معرفة

موقع عربي باتجاه RTL، مبني بـ TypeScript وواجهات Next.js App Router، ويستخدم Vinext/Vite للتشغيل والنشر عبر Sites. الخطوط محلية من عائلة ثمانية. لا توجد قاعدة بيانات.

## التشغيل

Node.js 22.13 أو أحدث:

```sh
npm install
npm run dev
npm run build
```

## إضافة المحتوى

أضف ملف JSON واحدًا داخل `content/articles` أو `content/prompts` أو `content/projects` أو `content/research` أو `content/resources` أو `content/certificates`. ثم أعد تشغيل التطوير أو البناء؛ يتولّد فهرس المحتوى تلقائيًا. لا تعدّل `content/index.ts` يدويًا.

استخدم أحد الملفات الموجودة نموذجًا. الحقول: `slug`, `title`, `description`, `category`, `date` بصيغة YYYY-MM-DD، `published`, `featured`, `tags`, و`sample`. الفقرات في `paragraphs` وتدعم `heading`, `text`, `code`, `quote`. المراجع في `references` وتحتوي `title` و`url`.

البرومبت: `prompt` للنص و`when` للاستخدام. المتغيرات مثل [CODE] تُبرز تلقائيًا.
المشروع: `technologies`, `year`, `github`, `demo`، والفقرات لدراسة الحالة.
الشهادة: `issuer`, `credential`, `image` اختياري، والتاريخ في `date`.

المحتوى الأولي تجريبي، معلّم بـ sample: true. لا توجد مشاريع أو شهادات أو خبرات مخترعة. أضف المحتوى الحقيقي قبل الإعلان العام. لم تُضف روابط GitHub أو بريد شخصية لعدم توفيرها.

## الروابط والبحث

كل محتوى منشور له رابط مستقل /section/slug. `searchIndex` جاهز لمحرك بحث محلي مستقبلًا. الصفحات تولّد عنوانًا ووصفًا وcanonical وOpen Graph وTwitter metadata. حدّث نطاق الموقع في app/layout.tsx وapp/sitemap.ts عند ربط نطاق آخر. لا توجد صور OG مولّدة؛ الأساس جاهز لإضافتها.

## التصميم

Display للعناوين، Text للقراءة، Sans للتنقل والمعلومات. خلفية سوداء موحّدة مع نص أبيض ورمادي وتوهّج أزرق خافت، وفق المرجع. الحركات تحترم prefers-reduced-motion. الأقسام الفارغة مقصودة حتى توفير المعلومات الحقيقية.


## لوحة إدارة المحتوى

افتح http://localhost:5173/admin بعد `npm run dev`.

- **مقال جديد:** العنوان، رابط مختصر، التصنيف، الوصف، الفقرات، الأكواد، الاقتباسات والمراجع.
- **برومبت جديد:** العنوان، الرابط، الوصف، وقت الاستخدام، والنص الكامل. زر النسخ يظهر تلقائيًا للزائر.
- **حفظ مسودة:** يحفظ على القرص، ولا يظهر في الصفحات العامة أو روابط التفاصيل.
- **نشر المحتوى:** يظهر في الفهرس والرئيسية. يمكن إلغاء نشره وإعادته لمسودة.
- **معاينة:** لقراءة المحتوى قبل نشره. البحث والفلاتر داخل اللوحة تساعدك على العثور على المحتوى.
- يبقى الرابط ثابتًا بعد أول حفظ حتى لا تنكسر الروابط المشاركة.

الإدارة الحالية **محلية فقط**. واجهة الحفظ متاحة على localhost أو 127.0.0.1 بمنفذ 5173 أثناء التطوير، وتُعطّل في بناء الإنتاج. النشر هنا يعني إظهار المحتوى في الموقع المحلي؛ لا يرفع الموقع للإنترنت. لا تستعمل هذه النسخة كلوحة إدارة عن بُعد. لذلك لا تطلب كلمة مرور محلية؛ الوصول مقصور على نفس الجهاز مع تحقق من المضيف والمصدر ورمز جلسة. عند الانتقال لاستضافة فعلية يجب ربط لوحة الإدارة بمصادقة خاصة بالمالك ومخزن دائم مناسب للاستضافة.

كل حفظ يكتب ملف JSON داخل مجلد المحتوى ويحدّث الفهرس تلقائيًا. قبل تعديل ملف موجود تُحفظ نسخة في `work/content-backups`. يتحقق المحرر من تعارض التعديلات لتجنب الكتابة فوق نسخة أحدث في نافذة ثانية. لا تُرفع النسخ الاحتياطية مع المصدر.

الاختبارات: `node --test tests/local-admin.test.mjs`.

## النشر على Cranl

المشروع جاهز للنشر باستخدام `Dockerfile`. الإعدادات المطلوبة في Cranl:

- Build Type: `Dockerfile`
- Port: `3000`
- Environment: `NEXT_PUBLIC_SITE_URL=https://YOUR-SUBDOMAIN.cranl.net`

Cranl يبني التطبيقات من مستودع GitHub. بعد ربط المستودع واختيار فرع `main`، ينفّذ Docker البناء ويشغّل التطبيق على `0.0.0.0:$PORT`.

لوحة `/admin` المحلية لا تُفعّل في نسخة الإنتاج، لأن نظام الملفات داخل حاوية Cranl مؤقت ويُمسح عند إعادة النشر. تفعيل إدارة المحتوى على الإنترنت يحتاج PostgreSQL وتسجيل دخول خاص بالمالك؛ لا تضع كلمة مرور أو اتصال قاعدة بيانات في المستودع، بل في Environment Variables داخل Cranl.
